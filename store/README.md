# ストア素材（App Store / Google Play）

`node store/build.mjs` で `store/out/` に全素材を生成し、アイコンは `assets/` へ自動配置する。
生成にはヘッドレス Chrome を使う（`/Applications/Google Chrome.app`）。外部ライブラリの追加は不要。

## デザインの出典

Claude Design プロジェクト「App Store素材案提示」より。

- **アイコン**: 案 7a のノート格子（マス＝一日）を地に、ターン8で 7a から派生した
  **公式キャラのバストアップ**を載せたもの。表情は `cheer`（深緑）。

  当初は 7a の全身像で作ったが、アプリ内のキャラが顔＋上半身のバストアップのため、
  ホーム画面とアプリ内で別のキャラに見えてしまっていた。両者を揃えるためバスト版に変更した。

  表情に `cheer` を選んだ理由:
  - 深緑（#2f6f4f）は地（#f3f2f2）との明度差が大きく、40px 表示でも顔が潰れない。
    `joy` の淡緑（#93a94e）は同条件で輪郭が曖昧になる（`store/out/` で比較検証済み）
  - 上げた腕が「迎える」しぐさになり、アイコンとして表情がつく
  - アプリを開いて未記録のときに出る表情と一致する（＝アイコンの顔で迎えられる）

  ★アイコンのマス座標は `src/components/Mascot.tsx` の `EXPRESSIONS` と同一。
  **片方だけ変更しないこと**（ホーム画面とアプリ内で別物になる）。
- **スクリーンショット**: ターン9のレイアウト（連番キッカー＋大見出し＋キャラ＋端末）。

## ★デザイン案からの意図的な逸脱

**端末内に描くUIは、デザイン案のモックではなく実装済みのアプリUIを再現している。**

デザイン案（9a）は回答UIを5色のスウォッチ（オリーブ→緑→黄→橙→赤）で描いていたが、
これは PROJECT_STATE.md の設計判断 **3-1 / 3-3** と衝突する:

> 回答UIに色のヒントを出さない。スコアの高低を示唆する色を付けると、
> 正直な自己申告より「良い色」を選びたくなるバイアスが生まれるため。

加えて App Store は「スクリーンショットが実際のアプリを反映すること」を求めるため、
実装に存在しないUIを載せると審査リスクと誇大表示になる。よって端末内は
`AnswerScale.tsx`（4段階評価・ニュートラル配色）、`CalendarGrid.tsx`（5段階配色）、
`app/onboarding/index.tsx`（実文言）に合わせてある。

同じ理由で、デザイン案 9c が描いていた「休む機能（月4日までグレーで残せる／連続記録は途切れない）」は
**アプリに未実装のため3枚目から外し**、実在する差別化点である「端末内保存」に差し替えた。
キャラ・見出し・レイアウトはデザイン案どおり採用している。

## 配色を変えるとき

`build.mjs` 冒頭の `APP` と `STAGE` は `src/constants/colors.ts` の写しなので、
アプリ側の配色を変えたらここも合わせること（ズレるとスクショが実物と食い違う）。
